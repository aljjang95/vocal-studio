# SMS bridge contract v1

## Owner routes (existing Access + protocol vs-cf-1 + same-origin mutations)
GET /api/sms/overview => {ok,settings:{enabled,mondayTime,tuesdayTime,mondayText,tuesdayText},device:{paired,lastSeen,relayOrigin},revision,weekStart,unassigned:[{id,name,phone,replied,scheduled}],messages:[{id,phone,text,direction,receivedAt,studentId,name,matchStatus,proposal:{date,time,warnings},status}],outbox:[{id,studentId,name,stage,status,createdAt}],aliasChanges:[{id,kind,oldName,newName,studentId}]}
POST /api/sms/pair {relayOrigin} => {ok,token,deviceId,relayOrigin}. Token displayed once; store hash; previous token revoked. HTTPS production origin only; localhost local-test explicitly.
POST /api/sms/revoke {} => {ok}; stop all queued sends.
POST /api/sms/settings {enabled,mondayTime,tuesdayTime,mondayText,tuesdayText} => {ok}; allowed configured eligible active flex recipients only. Text placeholders {name}. Default disabled, Mon10:00 Tue14:00 Asia/Seoul; editable owner settings. No cold late catchup: prepare within same Mon/Tue at due time, expire day end. No real sends without paired enabled device.
POST /api/sms/prepare {stage:'monday'|'tuesday'} => {ok,count}; manual bulk queued, idempotent stage/student/week. Same eligibility; Tuesday excludes any replied/scheduled after week's Monday. Fail if disabled/unpaired.
POST /api/sms/confirm {baseRevision,entries:[{messageId,studentId,date,time}]} => {ok,revision,count}. Atomic CAS: active flex only, duplicate/cancel/self/group preserved by scheduleSnapshot original engine; exact future date/time validate; append week override preserving slots and existing overrides; mark message scheduled only after same transaction record commit + broadcast. Any conflict/CAS returns409 nothing changed. No auto-confirm from text.
POST /api/sms/dismiss {messageId} => {ok}; only acknowledge card, no scheduling.
POST /api/sms/alias {aliasId} => {ok,revision}; CAS or strict current phone-match canonical student check, update displayed consult/inquiry alias names only on owner confirmation. No invented real name; multiple canonical students => held.

## Device routes (separate workers.dev relay; no public calendar/customer state)
Only Authorization: Bearer <pair token>. Private service binding SmsRelay.deviceRequest carries validated route+body. Allowed GET /device/pull, POST /device/event, /device/claim, /device/ack. Route/method/size limits enforced in relay and DO; token never logged/returned except owner pair; reject revoked tokens.
GET /device/pull => {ok,deviceId,allowedPhoneHashes:[sha256(normalizePhone)],messages:[{id,phone,text}],serverTime}. Poll prepares due reminders; pending only, no existing claimed replay. Names/calendar not returned. Phone first sync hashes, then filters both received and sent SMS BEFORE forwarding. Only current phone messages, no historical import. Phone numbers normalize Korean +82/0082 to0 and remove formatting, validate length9-11.
POST /device/event {id,phone,text,receivedAt,direction:'received'|'sent'} => {ok,matched,duplicate}. Max text4000/body16KiB; replay same id+payload only; unknown phone dropped without message persistence; distinct students same phone held (no alias mutation/schedule); sole authoritative student name used to identify consultation nickname suggestions. Received/sent direction from phone keeps original; no automatic replying/time choice. Reply suppresses Tue; recheck suppression at claim to avoid queued followup races.
POST /device/claim {id} => {ok,message:{id,phone,text}}. One-time queued->claimed after eligibility/reply/booking recheck. Claimed not automatically retried (avoid duplicates on uncertain delivery); token mismatch fails. No phone numbers before authorized pull.
POST /device/ack {id,status:'sent'|'failed'|'unknown',error?} => {ok}. Idempotent, status is SMS handed-to-modem, not proof delivered. Owner outbox distinguishes uncertain results. No auto retries on failures/unknown.

## Android app (new native/android-sms-relay isolated source)
Minimum26 target36, existing Unity OpenJDK/SDK36 compile tools only. Owner screen HTTPS relay URL + token password field; explicit start/stop; runtime READ_SMS/RECEIVE_SMS/SEND_SMS permissions; JobScheduler15min network poll plus one-shot receive jobs; SMS_RECEIVED joins multipart; sent-message provider observer/poll from setup boundary forwards ONLY hash-allowlisted numbers; persist event queue before network; idempotent retry. Keep token app-private only; no logging/body dumps; no historical/device contacts read. Claim before send; persist attemptStarted before SmsManager; don't auto-send again after crash; multipart all-part callbacks => aggregate sent/failed, persist ACK retries. JobScheduler may be delayed by Android power restrictions, no exact-minute promises. No customer SMS tests unless user-selected counterpart; no broad notification reads.

## UI (standalone sms-manager.js/css)
VSSms.open() modal, status+setup/download link, messages as escaped text, active students by canonical name, editable per-card date/time, checkboxes batch confirm. No date/time guesses in ambiguous text; raw text always visible. Read fresh owner overview; existing _vsSync ready/confirmed pending0 required for confirm/alias; CAS protects stale state. After authoritative mutation `_vsSync.retry()` and render existing UI only after server revision readback. Template preview and pair secret never captured in screenshot. Revoke disables device automation.

Physical S26 Ultra not connected (adb empty). Delivered APK/build/local E2E distinct from actual phone permissions, modem sending/receiving and battery reliability. No public/student calendar.
